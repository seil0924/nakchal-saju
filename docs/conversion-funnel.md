# 구매 전환 기록과 관심 질문

- `/admin/funnel`: 최근 7일, 대표 사주·투찰 택일. 유입 경로는 CEO/대표 유형/직접 진입.
- 기존 `page_views`의 별도 `kind=funnel_v1`에 여정 UUID·경로·상품·단계만 기록한다. 기존 조회수 쿼리에서는 제외한다. 추가 DB 마이그레이션과 권한 변경은 없다.
- 여정은 개인 식별자가 아니다. 이름, 출생 정보, 전화, IP, UA, 접근 토큰을 전환 이벤트에 넣지 않는다. 원래 리포트의 `input.journey`에는 결제 원장 대조를 위한 여정 정보만 추가한다.
- 동일 여정/단계는 클라이언트에서 중복 전송을 줄이고 서버 집계에서 Set으로 중복 제거한다. 저장소가 차단되면 메모리 중복 방지로 동작한다. 전송 실패가 구매를 막지 않는다.
- `paid`는 공개 이벤트 API에서 거절한다. 관리자 화면은 payments.status=paid와 reports.input.journey를 연결한다. 환불로 상태가 바뀐 주문은 현재 완료 집계에서 제외한다.
- 최근 7일의 단계별 관측 집합을 비교한다. 전환율의 분자는 두 단계를 모두 관측한 여정이다. 미관측은 확정 이탈이 아니며 기간 경계/광고 차단/지연 전송의 영향을 받는다. 이전 데이터에 소급 적용하지 않는다.
- 질문은 허용된 키(q)로 전달하고 `/api/report`에서 생성한 문장·대상 장을 원장에 저장한다. 클라이언트가 보낸 focus 본문은 버린다. 무료 응답에는 질문·장만 있고, 본문 접근 권한은 기존 게이팅을 유지한다.
- 구매 후, 모바일 결제 복귀, 보관함 재열람 모두 같은 focus 장을 먼저 펼친다. 이전 리포트는 기존 첫 장 규칙으로 동작한다.
